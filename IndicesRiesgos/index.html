3.2.6 Índice geoespacial

Diseñado para consultas por ubicación y distancia.

Ejemplo:

db.tiendas.createIndex({ubicacion:"2dsphere"})

Consultas típicas:

  • Tiendas cercanas
  • Rutas cercanas
  • Usuarios dentro de zona

3.2.7 Índices en Cassandra

Cassandra prioriza acceso por clave primaria y clustering columns. También soporta índices secundarios y vistas materializadas en ciertos escenarios.

Ejemplo:

CREATE INDEX idx_ciudad
ON clientes(ciudad);
Sin embargo, se recomienda evaluar cuidadosamente su uso en grandes volúmenes (Apache Software Foundation, 2024b).

3.2.8 Índices en Redis

Redis clásico utiliza la clave como acceso principal. En extensiones como Redis Search existen índices secundarios para texto y campos estructurados.

Ejemplo conceptual:

cliente:1001 → acceso directo por clave

3.2.9 Índices en bases de grafos

Motores como Neo4j indexan propiedades de nodos para acelerar búsquedas iniciales.

Ejemplo:

CREATE INDEX cliente_nombre
FOR (c:Cliente)
ON (c.nombre)

Después de localizar nodos, el motor recorre relaciones eficientemente.

3.2.10 Criterios de selección

Conviene elegir índice según:

  • Frecuencia de consulta
  • Cardinalidad del campo
  • Necesidad de ordenamiento
  • Búsquedas textuales
  • Ubicación geográfica
  • Costo de escritura adicional

3.2.11 Riesgos de exceso de índices

Demasiados índices pueden causar:

  • Inserciones más lentas
  • Mayor almacenamiento
  • Mantenimiento costoso
  • Complejidad administrativa
